# 1ms / 5ms 窗口：降低工具内部争用

本页保留首版 `a6e14570…` 的实现与未通过性能验收的历史结果，不代表当前默认构建。后续已完成分项定位及三组重复验收，见[短窗口资源争用修复](capture-contention-fix.md)。下方的波动、退化和当时暂缓推送决定均原样留证，不将旧成绩混作新结果。

## 首版实现

1. 分离目标成员表锁和观测交接锁；目标表交换后的旧 map 在锁外销毁，父进程 procfs 查询不占用成员表锁。ART 注册时的进程存活查询和最后引用销毁移到注册锁外；保留原检查，并在提交前额外重验锚点。
2. 待重试任务放在发布线程私有的最早到期堆，调整/取出在交接锁外完成；交接锁内仅处理 fresh 队列和额度。保留四个 fresh 后服务到期 retry 的公平性、最多四次尝试和退出 drain，不增加观测上限。
3. 32 槽单生产者/单消费者存储池预热并回收 4KiB 双读缓冲。发布者只在观测不再需要重试时归还；采集者持有的冻结观测不别名共享。大于 4KiB 的缓冲不进入池，失败捕获的私有 spare 也限制为一对 4KiB。
4. 捕获复用前，清空两遍字节、页覆盖/变化计数、时间、截断、截止和世代标记；未读尾部重新清零。guard 失败返回空的无效观测，绝不能把上一窗口内容或覆盖率当作本次证据。捕获范围、两遍顺序、guard 次数和 8ms 软预算不变。
5. 采集线程处理 trace 行时发布活跃提示，离开后保留 500µs 的近期提示。DEX/ART 扫描读前及发布任务开始前可让步：每个后台线程最多每 2ms 请求一次 200µs sleep。它只延后工作、不跳过范围或检查；持续事件下仍会继续扫描/发布。睡眠可能因调度延长，这不是实时期限或 CPU 占比保证。
6. 仅把本工具发布线程的 nice 相对降低三档、上限 19；使用自身 TID，不修改主线程、采集线程、目标线程、其他进程、CPU affinity/cpuset、全局 tracer 或 SELinux，不启用实时调度。设置失败记录警告并继续原优先级。纯轮询、snapshot/watch 不启动该发布线程或采集提示路径。

池额外预留约 256KiB 双读存储及元数据，另有一个有界 spare；私有重试堆最多预留 512 个任务结构。它们不是 ART 基线或排队数据额度，不把 32MiB 宣称为进程总内存上限。连续模式对象构造时预热池，即使该次后来降级为轮询也可能保留这一小额空缓冲；ART retained 计数仍只代表 ART 基线。

## 不变的安全边界

- 不缓存或省略 starttime、TGID/ABI、ART 对象/头部/虚表、Build ID、映射 backing 或实时补集检查。
- 不缩小采集范围来换命中率，不把单读当双读，不拼接尚未独立验证的跨事件方法字节，不选择冲突赢家。
- 32MiB/512 统一在途额度、32MiB 每秒采集计划量、64MiB 每周期补集计划量、256MiB 每运行产物上限均保留。
- `atomic_snapshot:false / plaintext_proven:false / mapping_aba_excluded:false` 等诚实标记不变；缓冲池不是明文缓存，也不是“已知方法引用”缓存。
- 更多让步和较低发布优先级也可能增加发布等待或发现延迟，故必须同时统计积压、丢弃、完整方法恢复和安全负例；不能只看成功样本的时延。

新增诊断 `Fast contention`：`buffer_hits / buffer_misses` 表示两遍存储容量是否足够，`handoff_contended` 只表示入队时 try_lock 未成功，不是全部锁等待或纳秒延迟；`scan_pauses / publication_pauses` 是请求让步次数；`publisher_nice` 是发布线程启动时成功设置的值，20 表示未启动或读取不可用，不保证系统之后不调整。

## 离线验证

- 14 组宿主逻辑测试通过。新增池测试覆盖冻结所有权、容量上限、短读尾部清零、guard/旧时间重置，以及 5000 次并发 SPSC 交接；提示策略测试覆盖活跃/近期状态、独立后台预算、持续流不无限暂停及异常下 RAII 释放。
- 原有 DEX/SO、ART、方法合并、冲突/补集、快速捕获和调度测试均回归通过。
- ARM64 / ARMv7 主程序、ARM64 原生测试及 JNI 夹具以 C++17、`-Wall -Wextra -Werror` 编译。ARMv7 不宣称支持 ARM64 ART profile。
- Windows MinGW 没有 `libasan`，可选 ASan 链接失败，**没有宣称 sanitizer 通过**。下方另列已经实际运行的 Root 原生测试与性能对照。

## 真机复测方法

使用同一 Root Pixel 6 / Android 16 和已适配的 `libdexfile` Build ID；若构建改变则停止，不猜偏移。只运行仓库自己的 `DexFile` / JNI 私有映射夹具，不注入或改写其他应用。

新增 `short-burst`：64 个不同方法分别只开放一次，32 个 1ms、32 个 5ms，交替排列、间隔 2ms；其余选中方法为零，头 44B 保持擦除。它避免重复同一方法几十次掩盖单次漏捕。fixture 的 `[begin,end]` 仍是 mprotect 返回之后记录的区间，边沿计数是保守下界；同一套 helper 同时用于基线/候选。
